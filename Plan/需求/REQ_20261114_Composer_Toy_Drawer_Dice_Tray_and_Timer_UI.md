## 1. 背景与定位

`#130` 行内标签的后端引擎与基础渲染已就绪，但当前用户在发送 `<roll=...>` 与 `<pin>...</pin>` 时仍需要手敲尖括号与英文表达式，手机 PWA 端尤其繁琐；同时 `<timer>` 目前在消息流中仅表现为素颜灰胶囊。

本需求为 `ChatComposer` 增加一个轻巧有趣的**游乐小抽屉（Toy Drawer）**，将用户端真正高频且有交互乐趣的 **`roll`（可爱骰盘）** 与 **`pin`（所见即所得多色便利贴）** 收拢进直觉化、高触感的玩具 UI 中，并同步将 **`timer`** 升级为玻璃沙漏样式。

> **范围边界**：抽屉内**只放 User 可用且好玩的 `roll` 与 `pin`**，不收入 `<block>`、`<spoiler>`、`<speak>`。

---

## 2. 入口设计：输入框“游乐小抽屉”

- **位置**：在 `ChatComposer` 底部左侧工具栏（与“选择图片附件 / 选择文件附件 / 开始录音”按钮并排）新增一个轻量按钮（如玩具匣 / 骰子组合图标）。
- **展开形态**：点击按钮，在输入框正上方轻盈展开小抽屉面板，提供清晰切换或并列的两块玩具区：**🎲 骰盘** 与 **📌 便利贴**。
- **禁言/禁用联动**：当处于 `#130` `<block>` 仅文本暂存状态或外部锁定禁用态时，若不支持附带标签可按既有 composer 规则同步约束；常规状态下，**允许用户不打正文、仅凭待发骰子或待发便利贴直接发送消息**。

## 3. 核心功能一：可爱骰盘（Dice Tray）

围绕“宝石多面骰不忍心直接砸桌子，所以需要垫着绒布的可爱骰盘”这一核心手感，严格区分 **“发送前自由把玩”** 与 **“发送后单次开奖”** 两个阶段：

### 3.1 选骰与拖放吸附（装盘阶段）
- **骰池与后端约束**：严格对齐后端白名单 `d4` / `d6` / `d8` / `d10` / `d12` / `d20` / `d100`，附带一个轻量 `+ / -` 整数常数修正步进器；实时校验并提示**单次总数 ≤ 8 颗骰子**。
- **视觉质感**：
  - 托盘主体呈现温柔的木框/织物天鹅绒底衬感（确保多面骰“落盘不磕角”）。
  - 骰子采用宝石切面多面体风格（可赋予核心主骰如 `d20` 温暖的橙黄宝石光泽，其他面数有清晰色彩区分）。
- **拖拽吸附交互**：
  - 支持从下方/侧边骰池把骰子**拖入**托盘区域——靠近托盘边缘时触发轻微磁吸高亮，松手即滑入盘内（触屏/便捷场景同时兼容直接轻点入盘，点击盘内骰子或拖出盘外可撤回）。

### 3.2 发送前：不关盘子就可以随便晃着玩
- **把玩规则**：只要抽屉处于打开、盘子尚未合上的状态，盘内的骰子就是“活”的 2D 刚体，用户可以随时在盘里滚着玩。
- **反“呆板点击”的 PC + 移动端物理交互**：
  1. **PC 光标拨弄与甩盘（Cursor Sweep & Flick）**：不靠呆板的鼠标左键单击；当光标快速划过盘内某颗骰子时，直接按光标瞬时速度向量 `(vx, vy)` 对骰子施加碰撞推力与旋转角动量；也可按住盘面拖动甩动整盘。
  2. **PC 长按空格摇晃（Hold `Space` to Rattle）**：当焦点在骰盘上（且未聚焦文字输入框）时，按住空格键相当于把托盘合掌连续摇晃，骰子高频震颤碰撞；一松手，骰子四散滚开并靠物理阻尼自然减速。
  3. **移动端摇一摇（`DeviceMotionEvent`）**：在手机/PWA 端晃动设备直接映射为盘内水平/垂直物理冲量（对不支持或未授权传感器的设备静默回退为触屏划拨/摇晃按钮）。
- **预览数字非固定**：试滚停下时显示的点数仅作为趣味预览（可用轻量水印或小字注明 `试滚中 · 发送后正式掷骰`），**绝不提交、不锁定、不构成重 roll**。

### 3.3 合上盘子（待发武装态）
- 当用户关闭抽屉 / 点“收起”合上盘子时，如果盘内已装入骰子，在输入框上方保留一枚紧凑的**待发骰袋徽章**（如 `🎲 已备 1d20+2d6+3`）。
- 点击徽章可随时重新掀开盘子增减或继续试晃；点击徽章上的 `×` 可清空待发骰子。
- **此阶段不调用任何随机开奖接口，不显示真实点数。**

### 3.4 按下发送：单次滚出与真值定格（不可重晃）
- **触发时机**：用户按下“发送”按钮时，前端将 `<roll=...>` 随正文（或纯 `<roll=...>`）送往后端由服务端计算真随机 `<roll_result>`。
- **视野滚入动画（单次只读）**：
  - 发送瞬间，原本收起在输入框处的骰子从视野下方**“哗啦”滚进聊天时间线视口中央偏下的半透明悬浮骰盘层**。
  - **锁定交互**：一旦进入发送开奖动画，**立即禁止任何晃动/拨弄干预**，用户只能观看这次干脆利落的单次滚动。
- **真值揭晓与淡出**：
  - 动画自然滚动约 `1.2s ~ 1.8s`（若后端尚未返回则平顺延续滚动直到结果到达），随后所有骰子靠阻尼减速，**精准翻面并定格在后端返回的 `roll_result.dice` 真实各颗点数上**（总和与明细简短亮起微光；`d20` 掷出 `20` 或 `1` 时可附带极轻量光晕彩蛋）。
  - 定格展示约 `1.5s` 后，悬浮骰盘整块优雅淡出；消息流中该条 user 消息保留永久的 `<roll_result>` 战绩芯片。
- **异常与无障碍降级**：
  - 若消息发送失败或开启 `prefers-reduced-motion: reduce`，不执行长动画（仅瞬间淡显/或直接回退草稿）。

## 4. 核心功能二：所见即所得多色便利贴（Sticky Note Draft）

### 4.1 纸片直写与色系预设
- **纸片编辑器**：在抽屉点击“贴便利贴”，直接展开一张复刻右上角 [PinBoard.tsx](file:///D:/Alicia/ExoCore_Project/ExoCore-Desktop/packages/app/src/features/chat/inlineTags/PinBoard.tsx) 胶带纸张美学的空白便利贴，光标直接落在纸面内部打字。
- **6 款高对比度预设颜色**（同时开放给 **User 点选** 与 **Assistant 标签书写**）：

| 预设名 (`color`) | 视觉描述 | 参考底色 (`--itag-paper`) | 参考纸缘 (`--itag-paper-edge`) | 文字墨色 (`--itag-ink`) | 备注 |
|---|---|---|---|---|---|
| `butter` | 经典鹅黄（默认） | `#f3e3a1` | `#e2cd7c` | `#3b3320` | 兼容无 `color` 参数的旧 `<pin>` |
| `mint` | 鼠尾草薄荷绿 | `#cbe5d4` | `#add1ba` | `#1f3829` | 清爽备忘 / 低负荷 |
| `blush` | 雾樱桃粉 | `#f4cdd4` | `#dfadb7` | `#462229` | 轻快日常标记 |
| `sky` | 晴空灰蓝 | `#cbe0f2` | `#a9c8e3` | `#1f3347` | 冷静记录 / 事项 |
| `lavender` | 薄雾丁香紫 | `#ded3f3` | `#c3b4e2` | `#2e2445` | 灵感 / 剧场线索 |
| `crimson` | 绯红暗墨纸 | `#521b24` | `#3b1118` | `#f5eadc` | 深色纸面配暖象牙字，高辨识度（尤适合阿莱指令或醒目警告） |

- 纸片下方提供一排直观的小圆点色卡，点选即实时变色。

### 4.2 点击区域外 → 暂时吸顶 & 发送前随时可改
- **草稿吸顶预览**：当用户在便签纸里写好内容后，**点击纸片外部任意区域**（或收起抽屉），该便签不丢失，而是平滑吸顶加入右上角 `.app-itag-pinboard` 便签栈中作为“**待发送预览便签**”（视觉上用浅虚线边框 + `待发送` 小角标与已落库便签明确区分）。
- **随时编辑/撤回**：在真正点击“发送”按钮之前，点击右上角任意一张`待发送`草稿便签，可重新弹出编辑纸片修改文字或切换颜色；点击其 `×` 按钮可直接撕掉作废。
- **随消息提交**：
  - 点击发送按钮时，将所有待发草稿便签按顺序拼装为 `<pin color="...">内容</pin>`（选 `butter` 时也可简写为 `<pin>...</pin>`）附在发送正文中一并送出。
  - **允许只贴便利贴不输入其他正文直接发送**；发送成功后清空本地草稿，待后端 `inline_state.pins` 刷新接棒展示；发送失败时草稿保留原位不丢失。
  - 若草稿内容本身包含字面 `</pin>`，组装前需安全转义或拦截提示以免破坏标签闭合。

## 5. 核心功能三：`<timer>` 沙漏前端美化

将 [InlineTagViews.tsx](file:///D:/Alicia/ExoCore_Project/ExoCore-Desktop/packages/app/src/features/chat/inlineTags/InlineTagViews.tsx#L140-L154) 中原本的普通 `<Chip>` 升级为精致的**玻璃沙漏微件**：

1. **`timer`（计时标签）**：
   - 使用 SVG 绘制双腔玻璃沙漏，呈现**上腔余沙高度、中间微动细沙流、下腔堆积沙丘**随时间比例流逝的动态效果。
   - 旁边显示 `倒计时 mm:ss`（或 `hh:mm:ss`）与可选 `title`（如 `泡茶`）。
   - **时间推算与过期兜底**：根据所属消息的 `createdAt + seconds` 与当前时钟计算剩余秒数；若加载历史消息时该计时器早已过期（或会话里已有对应的 `timer_fired`），沙漏自动静止于“上腔空、下腔满”的流尽完成态，避免对着三天前的老消息傻傻重跑倒计时。
2. **`timer_cancel`（取消计时）**：
   - 呈现为横卧或停流的静止灰调沙漏微件：`已取消 · {title}`。
3. **`timer_fired`（计时到点）**：
   - 保持后端触发定型文整行隐藏的既有规则（`timelineVisibility.ts`）；若在文本内联出现，则渲染为流尽泛暖光的小沙漏徽章。
