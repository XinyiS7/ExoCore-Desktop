## 1. 该板块以Agent为主体，project是边界，MemoryManager板块是附加功能* **极窄左侧导航 (Global Nav)：** 仅放 Agent, Project, Memory 的图标。* **可折叠侧边栏 (Sidebar - 约 250px)：** 根据你在导航栏的选择，这里显示 Agent 列表（及其设置入口）或 Project/会话列表。**在进入沉浸式会话时，这个侧边栏可以一键收起（Collapse）。*** **主舞台 (Main Stage - 占据剩余 100% 空间)：** 完整的 Session 会话区。* **资源 (Project Files)**把资源降级为**按需呼出的面板**。在 Project 视图下，在侧边栏或者会话顶部提供一个 `[📁 Project Files]` 按钮，点击后才从右侧滑出或弹出模态框（Modal）展示文件树。平时的文件调用，完全依靠你之前定的输入框 `@` 唤醒模糊搜索即可。* **分支与重试**  * **Regenerate (重新生成)：** 纯粹的 Overwrite 逻辑。点击后，后端重新推流，前端直接清空该气泡的原有内容并重新打字。不留历史包袱。* **Branch (分支)：** 采用类似 Git Fork 的逻辑。点击某条历史消息的 `[Y Branch]` 按钮时：1. 前端立刻触发路由跳转，进入一个新的 Session ID。2. 这个新 Session 逻辑有后台处理。3. 原会话保持原样。## 需补齐功能### 1. project 工作目录下的文件路径自动补全。这个需要后端在确认 project 的 work_dir 后向前端发送目录结构，还没做但是要留下来处理逻辑。和 cache 的自主轮询一样，在正在活跃的会话中，向后端询问目录结构，实时更新。基于“仅发送相对路径”的原则建立 `@` 文件挂载的数据流规约 (Data Flow Specification)**1. 前端表现 (UI Render)**当你选中文件后，输入框内生成一个不可编辑的块级 Token（例如带有一个小文档图标的 `[📄 src/utils/docking.py]`），它可以像普通字符一样被退格键删除，但不能修改内部文字。**2. 载荷解耦 (Payload Decoupling)**点击发送时，前端返回的是真实的文件相对路径字符串，以便 agent 能够准确获取：**3. Agent 自主执行 (Autonomous I/O)**Superior 接收到指令后，自主判断如何处理该路径。这意味着它有了操作的主权：它可以根据自己当前的上下文窗口余量，决定是全量读取、使用 `grep` 级工具只搜索关键字、还是通过解析器只抽取特定的类和函数块。前端对此完全不干涉。**4. 状态回传 (State Feedback)**为了填补等待期的黑盒感，在 Superior 后台执行读取动作时，前端会话流中应渲染一个暂态的步骤指示器（例如 `[⚡ Superior is reading src/utils/docking.py...]`），当读取完毕后自动折叠或变为打勾状态，随后再开始流式渲染 Markdown 回答。### 2. 勾选消息存入work_dir就是单纯地存 .md，用户可事后随时查看和修改。
